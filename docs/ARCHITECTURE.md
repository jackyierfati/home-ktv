# 设计说明

## 分工

- **客人**：手机或电脑打开点歌网页，找歌、点歌、遥控。不用登录，也不用知道有 NAS。
- **管理员**：管理页批量下载（按歌手、歌单、排行榜），管下载队列，更新曲库，改设置。
- **服务端**（NAS 上的 Docker）：曲库、已点、下载、歌曲文件，所有状态都在这里。
- **电视**：只负责播放。播放器照着服务端的状态放，自己不存歌、不管下载、不管队列。
- **麦克风**：不经过这套系统，用混音器处理。

```
手机 / 电脑 ──HTTP──▶ ktv-server（端口 8787）
                       ├─ 点歌网页 /、管理页 /admin、电视主页 /tv
                       ├─ 已点（room.py）──── 长轮询 ───▶ 电视播放器、手机
                       ├─ 下载队列（jobs.py）── 下载器（igeba_dl.py）── 可选代理 ──▶ i歌霸
                       ├─ 曲库（catalog.py，SQLite，可以从 i歌霸 在线重建）
                       └─ 歌曲文件 /media/<编号>（支持 Range）◀── 电视播放器
```

## 服务端（`ktv-server/server`）

只用 Python 3.11+ 标准库（`http.server`、`sqlite3`、`urllib`、`threading`），没有任何第三方依赖。

| 文件 | 内容 |
|---|---|
| `app.py` | HTTP 路由（JSON 接口和静态页面）、设置、把各部分接起来 |
| `room.py` | 已点队列、正在放的歌、播放状态、动态、每人点了几首唱了几首；存在 `data/room.json` |
| `jobs.py` | 下载队列：两个优先级，落盘，重启接着下，重新下载 |
| `igeba_dl.py` | 多线程分段下载器，也能单独在命令行用 |
| `catalog.py` | 曲库查询、搜索排序、从 i歌霸 重建曲库 |
| `igeba_api.py` | i歌霸 目录接口，重建曲库用 |
| `player.py` | 可选：把点歌和遥控转给电视上的麦动 |
| `repair.py` | 修复旧版下载器少了字节的文件 |
| `web/` | 点歌网页（`index`）、电视主页（`tv`）、管理页（`admin`） |

`data/` 下的文件：`igeba_catalog.db`（曲库）、`config.json`（设置，含 WiFi 密码）、`room.json`（已点和动态）、
`agent_state.json`（下载队列）、`repaired.json`（修复记录）。

### 已点和播放

- 服务端管队列。点歌时如果 NAS 上还没有这首歌，先以高优先级加入下载队列；歌留在已点里等，先放后面已经下好的；
  下好时如果没在放歌就自动开始。
- 正在重新下载的歌不算下好，不会拿旧文件去放；正在放的歌不能重新下载，换文件会把电视上那首放坏。
- 状态带一个版本号，客户端用长轮询拿：`?since=<上次的 version>&wait=3`，状态一变马上返回，没变最多等 3 秒。
  - 电视播放器：`GET /api/player/state`，放完、出错、播放进度用 `POST /api/player/report` 报回来。
  - 电视主页：`GET /api/tv/state`（谁点的、歌手头像、下载进度、动态、NAS 状态、WiFi 二维码）。
  - 手机：`GET /api/room`。
- 点歌时带昵称（`by`），动态里写「小王 点了《晴天》」，`users` 记每人点了几首、唱完几首（以后做麦霸榜用）。
- 「我点的」：点歌成功返回条目 `id` 和前面还有几首（`ahead`），手机把 id 存在 localStorage，同昵称点的也算；
  `/api/room` 里每首歌带歌长 `duration`，正在放的带进度 `position`，手机据此估「大约还要几分钟」。

### 下载器

i歌霸 的 CDN 每个请求最多给 2 MiB（Range 大了返回 403），从海外连过去单条连接很慢，而且时不时整条卡住。所以：

- 每首歌切成 512 KiB 的段（`KTV_CHUNK_KIB`），默认 64 路连接同时下（`--threads`）。
- 每段 20 秒没收到数据就放弃这次请求重下；第二次失败起换一个新的下载地址，最多重试 6 次。
- 拖尾对冲：只剩不多几段时，6 秒没收到数据的段再开一路，先下完的算数，不用等卡住的连接超时。
- 取下载地址的接口（`telnet.php`）偶尔不回应：每 5 秒并发再发一次，用最先回来的结果。
- 进度按实际收到的字节每秒报一次，网页上能看到真实的速度。
- i歌霸 把 Range 的右端点当成不包含（要 10 字节只给 9 字节）。每段多要 1 字节再截断，不够长就当失败重试，
  不会留下空字节。
- 先写 `<文件名>.part`，每个字节都写到了才 `os.replace` 成正式文件；重新下载时旧文件一直留到新文件完整为止。
- 下载队列有两个优先级：客人点的歌插到队首，批量任务排在后面；已经下好的自动跳过；队列存在硬盘上，重启后接着下。
- 下载走 `http_proxy` 环境变量（可以指向中国大陆出口的代理）；访问局域网的请求不走代理。

### 搜索排序

`catalog.ranked`：

1. 匹配程度：歌名或拼音完全相同 > 开头相同 > 包含。
2. NAS 上已经有的歌。
3. 上了几个歌单和排行榜。
4. 歌手热度（i歌霸 歌手列表本身就是按热度排的），合唱取最热门的那位。
5. 歌名短的在前。

按歌手搜时，先看搜中的是合唱里的哪位歌手、他有多热门，再看上面 2、3。歌手的歌和语种列表也按这个顺序，
所以管理页「每位最多 N 首」下的是最热门的 N 首。按歌名搜时，名字或拼音完全对上的热门歌手（前 300 名）
会在结果最上面给一个入口（`zjl` → 周杰伦 的歌）。

## 电视播放器（`ktv-player`）

- Android TV 应用，Kotlin + Media3 ExoPlayer，minSdk 24。
- 歌曲是 MKV：H.264 视频 + 两条 Vorbis 音轨，第一条原唱、第二条伴唱；切原唱/伴唱就是切音轨。
- App 只管放视频。上面盖一层透明 WebView，打开服务端的 `/tv`：主页、正在播放、已点列表、动态弹窗都是这个页面画的。
  `/api/tv/state` 返回的 `ui` 是页面文件的修改时间，页面改了电视会自己刷新，不用重装 App。
- 页面里的二维码由 App 用 ZXing 生成（`KtvNative.qr(text, size)`）；遥控器 ← 和返回键调用页面的
  `ktv.togglePanel()` / `ktv.hidePanel()`。
- 遥控器：OK 暂停/继续，→ 按两次切歌，↑↓ 原唱/伴唱，← 已点和二维码，长按 OK 改服务器地址；返回键只收起列表，
  退出用主页键（防止误按）。
- 退出再进来时，从服务端记的播放进度往回 2 秒接着放。

## 点歌网页和管理页

- 点歌网页（`/`）先保证手机好用，在电脑和 iPad 上自动变成两栏。只放客人用得到的功能：找歌、点歌、已点、遥控。
- 管理页（`/admin`）：按歌手、歌单、排行榜批量下载，下载队列（暂停、重试、清空），重新下载坏了的歌，
  更新曲库，设置名字、WiFi、播放器。
- 两个页面都没有密码，只在家里局域网用。
